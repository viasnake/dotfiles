# Japanese Writing Humanizer

LLM 生成や LLM 補助の下書きから、整いすぎた言い回し、空疎な反復、冗長な説明、翻訳調の硬さを取り除く。
目的は「立派な文章」に盛ることではない。
意味が通り、事実を増やさず、書き手の声が残り、読み手が自然に読める日本語へ戻す。

## 参照の使い分け

- LLM 臭さの検出で迷うときは `references/patterns.md` を読む。
- 日本語としての読みやすさ、語感、表記、敬語を整えるときは `references/japanese-style.md` を読む。
- 用途別の直し方や悪例・改善例が必要なときは `references/cases.md` を読む。
- 文法、語彙、かな・漢字、読解の土台から確認したいときは `references/language-foundations.md` を読む。

短い文章なら、この SKILL.md だけで作業してよい。
長い文章、公開前の文章、文体の判断が難しい文章では、必要な参照を読んでから直す。

## 守ること

- 事実、数値、固有名詞、日付、引用、コード、URL、主張の強さを変えない。
- 指示がない限り、元の文体、媒体、読者、書き手の距離感を保つ。
- 根拠のない評価、因果、将来予測、一般化を追加しない。
- 「AI 生成である」と断定しない。兆候と読みづらさだけを見る。
- きれいに均しすぎない。多少の揺れや温度が文章を生かしている場合は残す。
- ダッシュ類で装飾しない。日本語の地の文では、読点、括弧、文分割で処理する。
- 技術文書に限った規範をそのまま当てはめない。汎用文では、媒体と読み手を先に見る。

## 手順

1. 用途、読者、文体、変えてはいけない語句を把握する。
2. 不正確、曖昧、冗長、反復、宣伝調、翻訳調、表記ゆれを探す。
3. 意味が変わらない範囲で、まず局所修正する。
4. 空疎な段落は削るか、一文に圧縮する。
5. 長い文は分け、短文の連打は必要に応じてつなぐ。
6. 仕上げに、事実差分、文体差分、用語の揺れ、残った定型表現を確認する。

## 直す優先順位

1. 事実誤認や根拠のない断定。
2. 読み手が意味を取りづらい抽象語、主語抜け、係り受け。
3. LLM が出しがちな空句、反復、結論の水増し。
4. 翻訳調、表記ゆれ、敬語の過不足、句読点の不自然さ。
5. リズム、余白、書き手の温度。

## 書き換え方

- 抽象語を、見える事実や動作に置き換える。
- 余計な導入を削り、本文の用件、事実、問いにすぐ入る。
- 同じ主張を言い換えて重ねない。
- 箇条書きが機械的なら、自然な文に戻す。
- 評価語より、何が起きたかを書く。
- 弱めるべき主張では不確実性を残す。根拠なく弱いだけの語は削る。
- 日英混在文では、製品名、UI 文言、引用、専門語を不用意に訳さない。
- 仕上げで、まだ機械的に見える語をもう一度削る。

## 仕上げ監査

出力前に次を確認する。

- 事実、数値、固有名詞、日付、引用、コード、URL が変わっていない。
- 冒頭と結論がテンプレになっていない。
- 同じ意味の文が反復していない。
- 「重要」「不可欠」「多角的」「包括的」などの評価語が、根拠なく残っていない。
- 日本語の表記、敬語、句読点、語尾が文書内で大きく乱れていない。
- 英語やカタカナ語を、雰囲気だけで残していない。
- 書き手の声まで消して、無難で冷たい説明文にしていない。

## 出力

まず書き換え後の本文を出す。
必要な場合だけ、何を直したかを短く添える。
